# 마감 상태는 크론 없이 조회 시 계산한다

약속의 마감 시각이 지나도 DB의 `promises.status`를 즉시 `closed`로 바꾸는 예약 작업(Vercel Cron 등)을 두지 않는다. 조회는 서버 시각이 `voting_deadline_at` 이상이면 `collecting`을 `closed`로 계산해 돌려주고, 마감 이후 처음 들어온 쓰기 요청이 트랜잭션 안에서 DB 상태를 `closed`로 바꾼다(STATE-05-01, TIME-15-04). 마감 판정이 이미 "서버가 처리하는 시각 ≥ 마감 시각"이라는 요청 단위 규칙이라 크론 없이도 정확하고, Vercel 무료 플랜의 크론 주기 제약과 실패 재시도를 신경 쓸 필요가 없기 때문이다.

## Consequences

- DB에 `status = 'collecting'`인데 화면에는 마감으로 보이는 약속이 정상적으로 존재한다. `status` 컬럼을 직접 읽는 쿼리·통계는 반드시 마감 시각을 함께 비교해야 한다.
- 마감 시점에 알림(카카오 메시지 등)을 보내야 하는 기능이 생기면 이 결정을 다시 검토한다.
