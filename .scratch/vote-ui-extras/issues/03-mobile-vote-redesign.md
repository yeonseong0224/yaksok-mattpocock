# 03: 모바일 시간표 개편

**What to build:** 폭이 좁은 화면(sm 미만, 640px)에서 가능 시간 화면을 iPhone 와이어프레임(`yaksok-iphone16-wireframe.html`, 2026-11-16 사용자 제공) 모양으로 바꾼다. 7일(일~토)이 한 화면에 들어가고 시간은 위아래로만 움직인다. 데스크톱(sm 이상)은 그대로 둔다.

**Blocked by:** vote-ui-extras 02

**Status:** in progress

- [x] 모바일에서 7일이 가로 스크롤 없이 한 화면에 보이고, 시간표는 격자 안에서만 위아래로 움직인다. 날짜 머리글은 위에 붙어 있다
- [x] 선택한 시간은 문구 없이 채움으로만 보인다(이어진 선택의 위·아래 끝만 둥글게)
- [x] 날짜를 누르면 그날 시간을 시작·종료로 직접 고치는 시트가 열린다(구간 추가·삭제, 종료 ≤ 시작이면 오류, 지난 시간은 바뀌지 않음)
- [x] 아래 고정 영역: 요약 + "선택 내역" 시트, 내 가능 시간은 반복·제출, 전체 현황은 내 시간 보기·약속 확정하기
- [x] 탭(내 가능 시간·전체 현황), 주 이동(오늘·‹·›·주 이름 → 날짜 이동), 시간 선택·스크롤 모드 전환, 히트맵 범례
- [x] 후보 목록·조기 마감·다시 조율하기는 ☰ 약속 정보 서랍에 들어간다
- [x] 시간 상세·확정 확인·날짜 이동 팝업은 모바일에서 바텀시트로 열린다
- [ ] 실제 모바일 기기나 브라우저의 모바일 에뮬레이션에서 수동 확인

## Comments

- 2026-11-16 사용자 결정
  - 범위는 시간표 화면만. 설정·참여·초대·확정 결과 화면은 그대로.
  - 날짜를 누르면 시간 수정 시트만 연다(와이어프레임 그대로). 모바일에서는 하루 전체·오전·오후·저녁 버튼이 없다.
  - 후보 보기·조기 마감·다시 조율하기·후보 목록은 약속 정보 서랍 안에 둔다.
- 구현 메모
  - 모바일 여부는 `(max-width: 39.99rem)` 미디어 쿼리로 JS에서 고른다(`use-media-query.ts`). 격자 구조가 달라 CSS만으로 나누지 않았다.
  - 길게 누르기(2초) 반복 시트는 와이어프레임에 없지만 기존 기능이라 그대로 둔다.
  - 전체 현황의 "약속 확정하기"는 방장·마감 뒤에만 눌리고, 1순위 후보로 확정 확인 시트를 연다. 다른 후보는 서랍의 후보 목록이나 히트맵 칸 상세에서 고른다. 모집 중에는 "마감 후 확정할 수 있어요", 참여자는 "방장 확정 대기"(비활성), 확정 뒤에는 "확정 결과 보기".
  - 헤더의 "연성 · 방장" 표시는 2026-11-11 결정대로 넣지 않는다.
