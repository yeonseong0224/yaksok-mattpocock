# 두 번째 슬라이스: 약속 관리 (재설정 · 재조율 · 취소 · 탈퇴 · 내보내기)

## Problem Statement

첫 슬라이스로 약속을 만들고 확정까지 할 수 있지만, 한 번 시작한 약속은 손댈 수 없다. 날짜 범위를 잘못 잡았거나 마감을 당기고 싶어도 방법이 없고, 확정한 뒤 사정이 바뀌어도 다시 조율할 수 없다. 약속 자체를 접을 수도 없다. 참여자는 나갈 수 없고, PIN을 잊은 사람의 행은 정원을 계속 차지한다. 방장이 빠지면 약속을 관리할 사람이 없다.

## Solution

방장은 모집 중에 약속 이름, 날짜 범위, 정원, 마감을 바꿀 수 있다(재설정). 마감됐거나 확정된 약속은 새 마감을 정해 다시 모집 중으로 돌릴 수 있다(재조율). 방장은 약속을 취소할 수 있고, 취소된 약속은 모두에게 "취소된 약속입니다"만 보인다. 참여자는 언제든 스스로 나갈 수 있고, 방장이 나가면 가장 먼저 들어온 참여자가 자동으로 방장이 된다. 방장은 모집 중에 참여자를 내보낼 수 있다. 바뀐 내용은 다음에 화면을 볼 때 배너로 알린다.

결정 요약은 `docs/development/DECISION_CONFLICTS.md` 1-2절(2026-11-11)에 있다.

## User Stories

### 재설정 (모집 중 설정 변경)

1. 방장으로서, 모집 중에 약속 이름, 날짜 범위, 정원, 마감을 바꾸고 싶다.
2. 방장으로서, 하루 시간 범위(09:00~24:00)와 약속 길이(2시간)는 처음처럼 고정이라 고민하지 않아도 되길 바란다.
3. 방장으로서, 마감을 늦추는 것뿐 아니라 앞당기는 것도 하고 싶다. 새 마감은 처음 정할 때와 같은 규칙(지금부터 30분 이상 뒤, 날짜 범위 마지막 날 00:00 KST보다 앞)을 따른다.
4. 방장으로서, 정원을 늘리는 것뿐 아니라 현재 참여 중인 인원까지는 줄일 수 있길 바란다. 그보다 작게 하면 이유와 함께 거부당하고 싶다.
5. 방장으로서, 날짜 범위를 바꿀 때도 처음처럼 오늘(KST)부터, 양 끝 포함 최대 90일 안에서 고르고 싶다.
6. 방장으로서, 날짜 범위를 줄이면 범위 밖의 가능 시간이 지워진다는 것을 저장 전에 알고 싶다.
7. 방장으로서, 저장한 뒤 몇 명의 입력이 지워졌는지, 후보가 없어졌는지 보고 싶다.
8. 방장으로서, 마감이 이미 지난 약속은 재설정이 아니라 재조율로 안내받고 싶다.
9. 참여자로서, 범위가 줄어 내 가능 시간 일부가 지워졌다면 다음에 화면을 열 때 그 사실을 알고 싶다.
10. 참여자로서, 범위가 늘어 고를 수 있는 시간이 생겼다면 다시 확인해 달라는 안내를 받고 싶다. 이미 고른 시간은 그대로 집계되길 바란다.
11. 참여자로서, 방장이 설정을 바꾸는 동안 내가 고치던 입력이 낡았다면, 지금처럼 버려지고 최신 내용이 보이길 바란다(버전 충돌).

### 재조율 (다시 모집 중으로)

12. 방장으로서, 마감된 약속을(후보가 없거나 마음에 들지 않을 때) 다시 모집 중으로 돌리고 싶다.
13. 방장으로서, 확정된 약속도 사정이 바뀌면 다시 모집 중으로 돌리고 싶다. 이때 확정 일정은 해제된다.
14. 방장으로서, 재조율할 때 새 마감을 반드시 다시 정하고, 원하면 날짜 범위와 정원도 함께 바꾸고 싶다.
15. 방장으로서, 후보가 없다는 안내를 볼 때 재조율과 취소를 바로 고를 수 있길 바란다.
16. 참여자로서, 약속이 다시 모집 중이 되면 "다시 조율 중이에요" 안내와 함께 내 가능 시간을 고칠 수 있길 바란다. 이전에 고른 시간 중 범위 안에 남은 것은 그대로 있다.
17. 새로 오는 사람으로서, 재조율로 다시 열린 약속에 빈자리가 있으면 참여할 수 있길 바란다.

### 취소

18. 방장으로서, 모집 중·마감·확정 중인 약속을 취소하고 싶다. 되돌릴 수 없다는 확인을 거친다.
19. 참여자로서, 취소된 약속의 링크를 열면 "취소된 약속입니다"만 보이길 바란다.
20. 참여자로서, 취소되면 이 약속에서 로그인이 풀리고 다시 로그인할 수 없다.
21. 방장으로서, 설정 중(모집 시작 전) 약속은 취소 대신 "이 약속 없애기"로 지우고 싶다. 지우면 링크는 새 약속을 만들 수 있는 처음 상태로 돌아간다.

### 탈퇴와 방장 승계

22. 참여자로서, 모집 중·마감·확정 언제든 이 약속에서 나가고 싶다. 나간다는 확인을 거친다.
23. 참여자로서, 나가면 내 가능 시간은 집계와 후보에서 빠지고, 정원 자리가 비고, 이 기기에서 로그인이 풀리길 바란다.
24. 참여자로서, 나간 뒤 같은 닉네임으로는 다시 참여할 수 없다는 것을 알고 싶다.
25. 참여자로서, 확정 후에 나가면 확정 시각은 그대로이고 참석 명단에서만 빠지길 바란다.
26. 방장으로서, 내가 나가면 가장 먼저 들어온 참여자에게 방장이 자동으로 넘어간다는 것을 나가기 전에 알고 싶다.
27. 방장으로서, 남은 참여자가 없을 때 나가면 약속이 취소된다는 것을 나가기 전에 알고 싶다.
28. 새 방장으로서, 다음에 화면을 열 때 "방장 권한을 넘겨받았어요" 안내를 보고, 방장 기능을 바로 쓸 수 있길 바란다.
29. 확정 후 탈퇴로 참석 가능 인원이 2명 미만이 되면, 방장은 지금처럼 안내를 받는다(자동 해제 없음).

### 내보내기

30. 방장으로서, 모집 중(마감 전)이면 명단에서 참여자를 내보내고 싶다. 내보낸다는 확인을 거친다.
31. 방장으로서, PIN을 잊어 새로 들어온 사람의 예전 행을 내보내 정원 자리를 비우고 싶다.
32. 방장으로서, 나 자신은 내보낼 수 없다(나가기를 쓴다).
33. 내보내진 참여자로서, 다음에 화면을 열면 로그인이 풀리고 "방장이 이 약속에서 내보냈어요"를 보고 싶다. 같은 닉네임으로 재참여할 수 없다.
34. 참여자로서, 내보내진 사람의 가능 시간은 집계와 후보에서 바로 빠지길 바란다.

## Implementation Decisions

### 근거 문서

- 규칙 우선순위는 비즈니스 규칙 > ERD > API > PRD(R-06). 이번 결정은 `DECISION_CONFLICTS.md` 1-2절에 모았고, 각 규칙 문서와 API 문서 본문 반영은 티켓 01에서 한다.
- 이미 명세된 API를 따른다: 재설정 `PATCH /promises/{id}/settings`(STATE-API-03), 재조율 `POST /promises/{id}/reopen`(STATE-API-06), 취소 `POST /promises/{id}/cancel`(STATE-API-07), 본인 탈퇴 `DELETE /promises/{id}/participants/me`(STATE-API-08), 내보내기 `DELETE /promises/{id}/participants/{participantId}`(MEMBER-API-08). 1-2절 결정과 다른 부분만 고친다.
- ADR-0001: 마감은 조회할 때 계산한다. 쓰기 요청은 잠금 뒤 마감이 지났으면 먼저 closed로 바꾸고 원래 요청에 맞게 응답한다.

### 스키마

- 새 테이블·컬럼은 없다(ERD 5개 테이블 유지). 필요한 값은 이미 있다: `promises.status`(cancelled 포함), `cancelled_at`, `confirmed_start_at`, `participants.role`·`status`·`cancelled_at`·`availability_version`·`availability_submitted_at`, 세션 `expires_at`.
- 변경 이력 테이블을 만들지 않는다. 알림은 화면 배너로 하고, 브라우저가 마지막으로 본 상태와 비교한다.

### 모듈

- **설정 변경 영향 계산(깊은 순수 모듈)**: 입력은 이전 설정, 새 설정(날짜 범위·정원·마감), active 참여자별 슬롯·제출 여부, 서버 시각이다. 출력은 지울 슬롯(참여자별), 버전을 올릴 참여자, 제출 상태를 풀 참여자, 검증 오류다. 재설정과 재조율이 함께 쓴다. DB와 시계에 의존하지 않는다. 규칙은 다음과 같다.
  - 새 범위 밖 슬롯은 지우고, 범위 안 슬롯은 유지한다(STATE-04-02, 09-03).
  - 슬롯이 실제로 지워진 참여자만 버전 +1.
  - 고를 수 있는 슬롯이 하나라도 늘면(범위 확대·이동) active 전원의 제출 상태를 풀고 버전 +1(STATE-09-04). 줄기만 하면 제출 상태 유지.
  - 정원·마감·이름만 바뀌면 슬롯·버전·제출 상태를 건드리지 않는다.
  - 정원 < active 인원이면 `CAPACITY_BELOW_ACTIVE_COUNT`. 정원은 2~30명.
  - 날짜 범위는 오늘(KST)부터, 양 끝 포함 최대 90일. 마감은 지금+30분 이상, 마지막 날 00:00 KST 미만.
- **후보 계산 모듈(첫 슬라이스)**: 바꾸지 않는다. 다만 "제출을 마친 참여자" 기준을 X-07 결정에 맞게 바꾼다. 범위 확대로 제출 상태가 풀린 참여자도 남은 슬롯은 집계에 들어간다. 즉 후보 입력은 "한 번이라도 제출한 적 있는 active 참여자의 현재 슬롯"이다. 이를 구분할 값이 필요하면(예: 버전 > 0) 티켓에서 정하고 테스트로 고정한다.
- **멤버십 종료(탈퇴·내보내기·취소 공통)**: 참여자 `status=cancelled`, `cancelled_at` 기록, 그 참여자의 세션 즉시 만료. 슬롯은 보존하되 집계·후보에서 뺀다. 정원 집계에서 뺀다. 버전은 올리지 않는다.
- **방장 자동 승계**: 방장이 나가면 같은 트랜잭션에서 active 참여자 중 `created_at ASC, id ASC` 첫 사람을 host로 바꾼다. 없으면 약속을 취소한다(방장 행은 host·active 유지, ERD 6.2). draft에서 방장이 나가면 약속과 방장 행을 지우고 링크를 처음 상태로 돌린다(`draft_discarded`).

### API 계약 (기존 명세 기준, 바뀌는 점)

- 재설정: `DEADLINE_SHORTEN_NOT_ALLOWED`를 없앤다. 정원 감소 거부는 `CAPACITY_BELOW_ACTIVE_COUNT`로 통일한다. 하루 시간 범위·약속 길이는 받지 않는다(보내면 422 또는 무시, 티켓에서 기존 모집 시작 API와 같게 맞춘다). 응답의 `changeImpact`에 지워진 슬롯 수, 영향받은 참여자 수, 제출 상태가 풀린 인원, 후보 유무를 담는다.
- 재조율: `closed`·`confirmed`에서 허용. `votingDeadlineAt` 필수, 날짜 범위·정원은 선택. `confirmed_start_at`을 비운다.
- 취소: `collecting`·`closed`·`confirmed`에서 방장만. `draft`는 `INVALID_PROMISE_STATE`. 모든 세션 즉시 만료. 취소된 약속의 모든 조회·쓰기는 인증보다 먼저 `409 PROMISE_CANCELLED`(C-10). 링크 조회는 `promiseStatus: "cancelled"`.
- 본인 탈퇴: `collecting`·`closed`·`confirmed`, draft의 방장. 응답에 승계 결과(새 방장 participantId 또는 `promise_cancelled`, `draft_discarded`)를 담는다.
- 내보내기: 방장만, `collecting`이면서 마감 전. 자기 자신은 `CANNOT_REMOVE_SELF`. 이미 cancelled인 대상은 200(멱등).
- 탈퇴·내보내진 참여자가 다시 로그인하면 `401 UNAUTHENTICATED`(C-07, ERD 체크리스트 기준). 화면은 "이 약속에서 나갔거나 내보내졌어요"로 안내한다.
- 이전 방장이 승계 뒤 방장 요청을 보내면 잠금 후 role을 다시 확인해 `403`(EXCEPTION-09-01).

### 동시성

- 모든 쓰기는 첫 슬라이스와 같은 잠금 순서(링크 → 약속 → 참여자)를 따른다. 재설정·재조율·취소·탈퇴·내보내기와 제출·확정·조기 마감이 겹치면 먼저 잠근 쪽이 이긴다.
- 재설정 중 제출은 버전으로 막힌다. 슬롯이 지워진 참여자의 이전 버전 제출은 409(`AVAILABILITY_VERSION_CONFLICT`), 화면은 입력을 버리고 최신을 보여준다.
- 승계와 탈퇴가 겹쳐도(방장과 다음 순번이 동시에 나감) 약속 행 잠금으로 직렬화되어 남은 사람이 방장이 되거나 약속이 취소된다.

### 화면

- Figma에 이 흐름들의 화면이 없다. 기존 화면·컴포넌트로 구현하고 브라우저로 확인한 뒤 Figma를 코드에 맞춘다(2026-11-11 결정). 데스크톱과 모바일(약속 정보 서랍) 모두.
- 방장 메뉴: 약속 정보의 "방장 설정 보기"(읽기 전용, 방장만) 팝업에 모집 중이면 "설정 바꾸기", 마감·확정이면 "다시 조율하기", 그리고 "약속 취소"를 둔다. 설정 바꾸기와 다시 조율하기는 기존 설정 폼(약속 이름, 날짜 범위 달력, 정원, 마감)을 다시 쓴다.
- 후보 없음 안내("2명 이상 겹치는 시간이 없어요")에 방장에게 "다시 조율하기"·"약속 취소"를 둔다.
- 명단: 각 참여자 행에 방장에게만(모집 중, 본인 제외) "내보내기". 내 행 또는 약속 정보에 "이 약속에서 나가기". 방장이 나갈 때는 승계 대상(또는 취소됨)을 확인창에 보여준다.
- 확인창: 취소, 나가기, 내보내기, 범위 축소(지워질 입력이 있을 때)는 되돌릴 수 없음을 알리는 확인을 거친다.
- 취소된 약속: 링크를 열면 Figma 22(오류·빈 상태)의 형식으로 "취소된 약속입니다"만 보여준다.
- 배너(DB 없이): 브라우저에 약속별로 마지막으로 본 설정·상태·내 역할·내 슬롯 수를 기억한다. 다음 조회에서 달라졌으면 한 번 보여준다.
  - 날짜 범위·마감·정원이 바뀜 → "방장이 설정을 바꿨어요"(지워진 내 입력이 있으면 함께).
  - 범위가 늘어 내 제출 상태가 풀림 → "고를 수 있는 시간이 늘었어요. 다시 확인하고 제출해 주세요."
  - 재조율로 다시 모집 중 → "다시 조율 중이에요".
  - member → host → "방장 권한을 넘겨받았어요".
  - 다른 기기에서는 한 번 더 보일 수 있다(알고 내린 결정).
