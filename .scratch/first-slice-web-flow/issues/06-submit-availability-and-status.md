# 06: 가능 시간 제출과 현황 (기본)

**What to build:** 참여자가 30분 슬롯 격자에서 클릭으로 가능 시간을 고르고 제출하면, 5초 안에 다른 참여자 화면의 시간표와 가능 인원("3/5명")에 반영된다. 제출한 뒤에도 마감 전까지는 다시 제출할 수 있다. 마감 시각이 지나면 제출이 거부되고 약속이 마감된 것으로 보인다.

스펙: User Stories 36, 42~46, 48~55, 57. API: TIME-API-01, TIME-API-02. ADR-0001.

**Blocked by:** 04

**Status:** ready-for-agent

- [ ] 제출은 active 참여자 본인만, effectiveStatus가 collecting일 때만 할 수 있다
- [ ] 제출하면 다음과 같이 처리한다
  - 미래 슬롯은 전체 교체한다
  - 요청에 섞인 지난 슬롯은 무시하고, 이미 저장된 지난 슬롯은 보존한다
  - 범위 밖 슬롯은 빼고 저장한다
  - 제출 시각을 기록하고 version을 1 올린다
- [ ] baseVersion이 다르면 409 `AVAILABILITY_VERSION_CONFLICT`, 슬롯이 5,000개를 넘으면 422 `SLOT_LIMIT_EXCEEDED`
- [ ] 빈 배열로 제출할 수 있다. 화면에서는 "모두 불가능으로 제출됩니다"라고 확인을 받는다
- [ ] 마감 판정(ADR-0001)
  - promises 행을 FOR UPDATE로 잠근 뒤 DB 시각으로 판정한다. 그 시각이 마감 시각 이상이면 거부한다
  - DB 상태가 아직 collecting이면 closed로 바꿔 커밋한 뒤 409를 돌려준다
  - 테스트는 `voting_deadline_at`을 과거로 바꿔 재현한다
- [ ] 현황 조회는 `serverTime`과 참여자별 제출 슬롯을 돌려준다. 미제출자와 빈 선택 제출자는 모든 시간에 불가능으로 보인다. 분모는 active 참여자 전체다
- [ ] 화면(브라우저에서 수동 확인)
  - Figma 07·13~17·21 기준: 주간 7일 격자(세로 시간, 가로 날짜), ‹ ›로 7일 이동, 월 제목을 누르면 날짜 이동 팝업, 화면을 이동해도 선택 유지, 클릭 선택, 제출 버튼, 히트맵(시간별 가능 인원, 색상 + 숫자)
  - 미응답 구분은 표시하지 않는다(명단의 "응답 완료", "미응답 N명" 없음)
  - 지난 칸은 `serverTime` 기준으로 구분하고, 시각은 한국 시간으로 표시한다
  - 캘린더가 보이는 동안에만 5초마다 조회한다(SWR)
  - 마감 후에는 읽기 전용
