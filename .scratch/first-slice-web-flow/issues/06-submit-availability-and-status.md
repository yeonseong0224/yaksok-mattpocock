# 06: 가능 시간 제출과 현황 (기본)

**What to build:** 참여자가 30분 슬롯 격자에서 클릭으로 가능 시간을 고르고 제출하면, 5초 안에 다른 참여자 화면의 시간표와 가능 인원("3/5명")에 반영된다. 제출한 뒤에도 마감 전까지는 다시 제출할 수 있다. 마감 시각이 지나면 제출이 거부되고 약속이 마감된 것으로 보인다.

스펙: User Stories 36, 42~46, 48~55, 57. API: TIME-API-01, TIME-API-02. ADR-0001.

**Blocked by:** 04

**Status:** ready-for-agent

## Comments

- 2026-11-10: API·화면 구현(`feat/submit-availability`). 남은 것: 화면 브라우저 수동 확인.
  - 오류 형식은 time.md의 `{"error":{...}}`가 아니라 공통 규약 `{code,message,details}`를 따르고, 본문 모양 오류는 400 `INVALID_REQUEST`다(API_CONVENTIONS 3장).
  - 화면은 고치기 시작한 시점의 버전을 기준 버전으로 보낸다. 그 사이 다른 기기가 제출했다면 409로 막히고 최신 값을 다시 받는다. 폴링에서 버전이 바뀌었을 때 로컬 입력을 버리고 안내하는 것은 07에서 한다.
  - "마감 뒤 첫 쓰기 요청이 DB를 closed로 바꾼다"는 조회로 관찰할 수 없어서 이 테스트만 DB 값을 직접 확인한다.
  - 용어집에 맞춰 화면 이름을 "가능 시간 화면"으로 하고 "투표" 표현을 뺐다(설정 폼의 "③ 투표 마감"도 "③ 응답 마감"으로).
