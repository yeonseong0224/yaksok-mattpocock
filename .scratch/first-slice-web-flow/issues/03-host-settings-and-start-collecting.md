# 03: 방장 설정과 모집 시작

**What to build:** 방장이 약속 이름, 날짜 범위(월간 달력에서 시작일·종료일 클릭), 정원, 마감을 설정하고 모집을 시작하면 약속이 collecting이 되고 초대 링크 화면이 나온다. 하루 시간 범위(09:00~24:00)와 약속 길이(2시간)는 MVP에서 서버가 기본값으로 저장한다. 설정 중 화면을 보던 사람은 새로고침하지 않아도 다음 화면으로 넘어간다. 방장이 10분 안에 설정을 끝내지 못하면 draft가 만료되고, 다음 사람이 새 방장으로 등록할 수 있다.

스펙: User Stories 5~7, 10~19. API: STATE-API-01, STATE-API-02. 규칙: STATE-02-02, STATE-03-01, TIME-03-01·04-01~03·05-01/02·06-02/03·13-01~03·14-01/02.

**Blocked by:** 02

**Status:** ready-for-agent

- [x] 약속 상태·설정 조회: 비로그인 사용자는 상태만, 참여자는 설정까지 본다. 시각은 ISO 8601 + `+09:00`, 하루 시간 범위는 HH:mm로 표기한다
- [x] 모집 시작 시 아래 조건을 검증하고, 어긋나면 필드별 이유와 함께 거부한다
  - 약속 이름: 앞뒤 공백 제거 후 1~30자(화면에 보이는 글자 기준. 이모지 한 개 = 1자. DB는 상한을 검사하지 않으니 서버가 검증)
  - 정원: 2~30명
  - 날짜 범위: 시작일은 오늘(KST) 이후. **범위 길이**가 양 끝 포함 최대 90일(종료일 ≤ 시작일 + 89일). 시작일이 먼 미래여도 길이만 맞으면 허용한다
  - 종료일: 그날 00:00(KST) 전에 고를 수 있는 마감(처리 시각 + 30분을 30분 단위로 올린 시각)이 있어야 한다. 그래서 오늘 하루만 고를 수는 없고, 23:00이 지나면 내일도 고를 수 없다(TIME-14-02 보충·정정)
  - 마감: 처리 시각보다 30분 이상 뒤, 범위 마지막 날 00:00(KST)보다 앞
- [x] 테스트에 넣을 사례: 시작일이 미래인 89·90·91일 범위, 오늘 하루 범위(거부), 23:45 기준 내일 종료일(거부)
- [x] 모집을 시작하면 그 약속의 모든 세션을 `voting_deadline_at + 7일`로 늘리고, 이후 응답의 Set-Cookie로 쿠키 Max-Age도 늘린다(MEMBER-06-03)
- [x] 하루 시간 범위와 약속 길이는 요청으로 받지 않고 540~1440분, 120분으로 저장한다
- [x] 필수값이 하나라도 빠지면 모집을 시작할 수 없다
- [x] 모집 시작은 방장만 할 수 있다. 멤버와 비로그인 사용자는 거부한다
- [x] draft 10분 만료 처리
  - GET 요청은 만료 여부를 계산만 한다
  - 쓰기 요청은 잠금을 얻은 뒤 DB 시각으로 판정하고, 세션 → 방장 참여자 → promise 순서로 삭제한다. 링크는 미사용 상태로 되돌린다
  - 테스트는 `created_at`을 과거로 바꿔 재현한다
- [ ] 설정 폼(Figma 01~03): 약속 이름, 월간 달력 날짜 범위(이전·다음 월. 지난 날짜는 비활성. 시작일을 고른 뒤에는 시작일 + 90일 이후와 위 조건을 만족하지 않는 종료일을 비활성), 정원 −/+, 마감(KST, 30분 단위). 마감 기본값은 지금부터 24시간 뒤를 30분 단위로 올림한 시각(범위 마지막 날 00:00 KST보다 앞이 되도록 맞춤). 안내 문구는 "최대 90일"
- [ ] 초대 링크 화면(Figma 04): 약속 이름, 범위, 정원, 마감 요약 / 링크 복사(토스트) / "내 가능 시간 입력하기"
- [ ] 설정 중 화면이 주기적으로 조회해서 collecting 전환이나 draft 만료를 감지하면 화면을 바꾼다. 브라우저에서 수동 확인
