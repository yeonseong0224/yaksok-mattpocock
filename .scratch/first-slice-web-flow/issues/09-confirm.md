# 09: 확정

**What to build:** 방장이 마감된 약속에서 표시된 후보 하나를 골라 확정하면 약속이 confirmed가 되고, 모두가 확정된 시작·끝 시각과 참석 가능한 사람을 본다. 방장이 후보를 본 뒤 상황이 바뀌어 그 후보가 더 이상 유효하지 않으면, 확정이 거부되고 새 후보 목록을 받는다.

스펙: User Stories 67~72. API: STATE-API-05. 규칙: STATE-07-01, RESULT-11-02, 12-01/02, 13-01/02.

**Blocked by:** 08

**Status:** ready-for-agent

- [ ] 확정은 방장만, effectiveStatus가 closed일 때만 할 수 있다. collecting이면 조기 마감을 먼저 하라고 응답하고, 멤버는 거부한다
- [ ] 서버가 05 모듈로 후보를 다시 계산해서, 요청한 시작 시각이 표시 후보가 아니면 409와 새 후보 목록을 돌려준다
- [ ] 가능 인원만 바뀌었고 여전히 표시 후보라면 그대로 확정한다
- [ ] `confirmed_start_at`만 저장하고, 끝 시각은 약속 길이로 계산해 응답한다
- [ ] 확정 후 참석 가능한 사람은 현재 제출값 기준으로 다시 계산해 보여준다
- [ ] 화면(Figma 18·19·20): 시간 상세 팝업의 "이 시간으로 확정하기"는 방장에게만, 마감 후에만, 그 칸이 표시 후보의 시작 시각일 때만 보인다. 확정 확인 팝업(날짜, 시작·끝, 가능 인원) → 확정 결과 화면(읽기 전용). 방장이 참석할 수 없는 후보라면 확인 팝업에 방장 불참 안내를 보여준 뒤 확정한다(RESULT-04-02). 브라우저에서 수동 확인
