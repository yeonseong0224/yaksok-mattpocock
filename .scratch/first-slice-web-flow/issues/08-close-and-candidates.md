# 08: 마감과 후보 공개

**What to build:** 방장이 조기 마감하거나 마감 시각이 지나면 약속이 마감되고 최종 후보가 공개된다. 모집 중에도 참여자들은 현재 제출값 기준의 후보를 실시간으로 본다. 후보마다 참석 가능한 사람의 닉네임이 보이고, 후보가 없으면 안내가 뜬다.

스펙: User Stories 56~66. API: STATE-API-04, 후보 조회. 규칙: STATE-05-01~03, RESULT-08-01, 09-01/02, 10-01.

**Blocked by:** 05, 06

**Status:** ready-for-agent

- [x] 조기 마감은 방장만, collecting일 때만 할 수 있고 상태를 closed로 바꾼다. 멤버는 거부한다
- [x] 조기 마감하면 그 약속의 모든 세션을 실제 마감 처리 시각 + 7일로 맞춘다(MEMBER-06-03)
- [x] 조기 마감한 약속에 다시 로그인할 때 새 세션의 기준 만료도 "실제 마감 처리 시각 + 7일"이어야 한다. 지금 `loginSessionExpiresAt`(lib/members/session.ts)은 `voting_deadline_at + 7일`을 기준으로 쓴다. 조기 마감 때 마감 처리 시각을 남길 방법(예: `voting_deadline_at`을 처리 시각으로 바꾸기)을 정하고 함께 고친다(티켓 04 리뷰)
- [x] 조기 마감과 제출이 동시에 들어오면 promises 행 잠금 순서로 직렬화되어, 먼저 잠금을 얻은 쪽이 이긴다
- [x] 참여자 전원이 제출해도 자동으로 마감되지 않는다
- [x] 후보 조회는 05 모듈로 계산하고, 제출을 마친 active 참여자만 반영한다. 기준 시각은 서버 시각이다
- [x] 모집 중이든 마감 후든, 로그인한 참여자에게 후보와 후보별 닉네임을 공개한다
- [x] 후보가 없으면 "2명 이상 겹치는 시간이 없어요"라고 안내한다
- [ ] 화면(Figma 17·18·21): 모집 중에는 "일정 확정하기" 자리에 방장용 "조기 마감" 버튼. 후보 확인(시작·끝, 가능 인원, 닉네임). 히트맵 칸을 누르면 시간 상세 팝업(가능/불가능만, 미응답 구분 없음). 마감 후 읽기 전용 표시. 브라우저에서 수동 확인

## Comments

- 2026-11-10: API·화면 구현(`feat/close-and-candidates`). 남은 것: 화면 브라우저 수동 확인.
  - 조기 마감하면 `voting_deadline_at`을 실제 마감 처리 시각으로 바꾼다. 그래서 세션·재로그인 세션 모두 "실제 마감 처리 시각 + 7일"(state.md STATE-API-04에 기록).
  - 후보 조회는 모집 중에도, 닉네임 포함, 최대 5개(페이지 없음)로 구현(state.md STATE-API-10에 기록).
  - 조기 마감과 제출의 동시 요청은 둘 다 링크 → 약속 잠금을 잡으므로 먼저 잠근 쪽이 이긴다. 이 경합은 자동 테스트로 재현하지 않았다.
  - 시간 상세 팝업의 "이 시간으로 확정하기"는 09에서 더한다.
  - state.md에서 STATE-API-04·05·10에 잘못 들어가 있던 "비로그인은 200 상태만" 메모를 지웠다. 티켓 03에서 STATE-API-01에만 넣으려던 것이 문자열 치환으로 여러 절에 들어간 실수였다(05 확정 절 포함).
  - 후보 패널은 모집 중에도 처음부터 펼쳐 둔다(스토리 59). 조기 마감 확인 문구는 방장 본인의 제출하지 않은 변경이 사라진다는 것도 알린다.
